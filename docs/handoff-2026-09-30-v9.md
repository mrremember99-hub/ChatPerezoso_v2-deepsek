## Bugs encontrados en prueba manual

### Bug 1 — tool_call sin 'name' (fix `9681523`)

**Síntoma:** T.2 fallaba con `Error: tool_call sin 'name'`.

**Causa:** `OllamaAdapter.chat()` pasaba el dict crudo de Ollama
(`{id, function:{name, arguments}}`) a `ModelDelta`, pero
`HarnessSession._execute_tool_call` espera `{name, arguments}`.

**Fix:** aplanar en el adapter cuando llega formato Ollama nativo.
Retrocompatible: si ya viene plano, se pasa tal cual.

**Tests:** 2 tests viejos actualizados al contrato correcto +
1 test nuevo explícito del aplanado.

### Bug 2 — generación sin límite (fix `553ffe2`)

**Síntoma:** tras tool calls, el modelo seguía generando texto
indefinidamente (sin cancelar, no cerraba).

**Causa:** `config.json` tiene `num_predict: 0` (= sin límite).
`OllamaClient` respeta ese 0. El legacy cierra en 25s porque el
modelo decide parar; el harness tarda más (prompt más grande con
tool schemas + system prompt distinto).

**Fix:** `_build_harness_worker` aplica `num_predict=2048` por
defecto si el config no lo fija. Solo afecta al harness.

**Comparativa:** legacy 25s vs harness 25s tras el fix.

## Cómo activar el harness para pruebas

Flag `_harness_enabled` está en `ChatController.__init__`,
línea ~148, OFF por defecto. Activar:

    python3 -c "
    from pathlib import Path
    p = Path('ui/controllers/chat_controller.py')
    t = p.read_text()
    old = '        self._harness_enabled = False\n'
    new = '        self._harness_enabled = True  # TEMP\n'
    assert t.count(old) == 1
    p.write_text(t.replace(old, new))
    "

**NO commitear con el flag en True.** Revertir antes.
