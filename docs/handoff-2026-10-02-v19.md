## Reglas nuevas / reforzadas

**#30 (reforzada, falló 4 veces esta sesión)**:
Antes de `git add` → `git diff --stat` debe listar TODOS los ficheros
esperados. Si un fichero no aparece, la edición no ocurrió. No stagear
a ciegas.

**#31 (nueva)**:
Un script de edición que sale con `FALLO:` a mitad deja escritos los
ficheros que se escribieron antes del `sys.exit`. Próximo script:
construir todo el contenido en memoria y hacer un solo `write_text` al
final, o dividir en scripts independientes por fichero.

**#32 (nueva)**:
Antes de usar un string literal (con acentos, caracteres especiales)
como clave de búsqueda en `sed`/`str.replace`, verificar contra el
fichero real. En 7c falló por `extension` vs `extensión`.

**#33 (nueva)**:
Todo `git rm` va seguido de verificar el diff **antes** del `git add`.
El `git rm` limpia el índice; los ficheros que había que **modificar**
en el mismo commit se quedan fuera si no se comprueba.

## Protocolo de commit obligatorio (a partir de aquí)

1. Ejecutar todas las ediciones.
2. `git diff --stat` — debe listar TODOS los ficheros esperados.
3. `pytest -q tests/ 2>&1 | tail -3` — verde.
4. `git add <lista explícita>` (no `git add -A`).
5. `git diff --cached --stat` — debe coincidir con paso 2.
6. `git commit`.
7. `git show --stat HEAD` — debe coincidir con paso 5.

Si cualquier paso falla, parar y pegar la salida. Mejor commit tardío
que commit roto.
