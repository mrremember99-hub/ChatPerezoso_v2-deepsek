### Lo que el harness YA hace

- Ciclo completo de agente: `step(user_message)` → modelo →
  tool calls → resultado → modelo, hasta que el modelo pare o
  se exceda `max_tool_rounds=15`.
- Emite 20+ tipos de eventos en streaming.
- Persiste cada evento al EventLog SQLite WAL si se inyecta.
- Detecta bucles (4 patrones) e inyecta prompt correctivo.
- Monitoriza salud (loop/stuck/thrash/runaway).
- Gate de confirmación vía `confirmation_handler` inyectado
  (S4-d). Sin handler → deniega; con handler → aprueba/deniega.
- Idempotencia por clave `sha256(run_id|step|call_id)`.
- Resume desde checkpoint: `load_state` + `detect_inconsistencies`
  + `plan_resume`.
- Compila tool schemas a texto token-efficiente.
- VRR-Stop: heurística simple de parada del bucle verificar-reparar.
- Completion verification: parsea fases del prompt, verifica que
  las tools requeridas se ejecutaron y la verificación pasó.

### S6 — el cambio crítico

S6 es donde `HarnessSession` sustituye a `ChatWorker`. Riesgos:

- `ChatWorker` tiene 800+ lineas y 10 señales Qt cableadas a
  `ChatController` (`tool`, `tool_result`, `confirmation_requested`,
  `stream_ready`, `metrics_updated`, `summary_ready`, `finished`,
  `error`, `cancelled`, `tool_auto_approved`).
- `HarnessSession` emite eventos, no señales Qt.
- **Opcion A**: escribir `ui/harness_bridge.py` (QObject) que
  traduzca eventos → señales existentes. `ChatController` casi no
  cambia.
- **Opcion B**: refactorizar `ChatController` para consumir
  eventos directamente. Mas limpio a largo plazo, mas cambios.
- **Mi voto**: Opcion A. Es reversible, y valida el harness en
  produccion sin reescribir el controller.

**Antes de S6**: escribir un documento de diseño
(`docs/harness-s6-migration.md`) con la traduccion evento→señal
y los tests que migran.

## REGLAS DE PROCESO

1. **Un paso por bloque**. Tests y commits en bloques separados con `PARA. Pégame la salida`.
2. `str.count(old) == 1` obligatorio en scripts de patch.
3. Tras cada apply: `git diff --stat` **antes** de `pytest`.
4. `_ChatContext` (dataclass): campos nuevos con default al final.
5. Tests del controller con `__new__` + asignación manual: `getattr` defensivo.
6. Editable install + carpeta movida = `.pth` huérfano que rompe Python.
7. **Antes de tocar `httpx.post`/`httpx.get`/`httpx.AsyncClient`**: 7 archivos de test los mockean.
8. **NUNCA triple-backtick dentro de strings Python en heredocs.**
9. **Un `cat > file << EOF` por bloque**, o `/tmp/apply_*.py` atómico.
10. **Tests con `AstIndex(root)` sin `db_path`**: fixture autouse monkeypatch `CACHE_DIR`.
11. **Tests que referencian `_SCHEMA_VERSION`**: importar la constante.
12. **ruff con `.ruff.toml`**: `select = [E,F,W,I,UP,B,SIM,C4,RET,RUF]`.
13. **mypy lee `pyproject.toml`**: `files = ["core","ui","plugins"]` (el harness se incluye por estar bajo core/).
14. **Auditoría externa usa `P#N`**: mantener nomenclatura en commits.
15. **Strings con `\n` dentro de `/tmp/apply_*.py`** → usar `r'''...'''` (raw).
16. **Tests con Qt que inicializan widgets** → verificar aislado antes de commitear.
17. **Quotes anidados en literales vía `write_text()`** → delimitador opuesto.
18. **Patch que reemplaza `old` por `new` donde `old` es prefijo de `new`** → `str.count(old) == 1` NO protege. Anclar `old` con línea posterior.
19. **Endurecer una función** → revisar **también los casos positivos** del test.
20. **Markdown del handoff** → `cat > file << 'MDEOF'` en chunks (triple-backticks anidados rompen el pegado).
21. **SQLite compartido entre threads**: `check_same_thread=False` NO basta. RLock propio.
22. **Módulos con `RLock`**: exponer helpers `cursor()` / `commit()` que tomen el lock.
23. **Allowlist con args inválidos**: decidir `auto` después de validar el tipo.
24. **Mensajes de tool result deben distinguir** timeout de rechazo explícito.
25. **`cat > file << 'EOF'` con contenido >3 KB** se corta al pegar. Partir en chunks <2 KB o usar `/tmp/apply_*.py`.
26. **Handlers opcionales inyectados** (como `confirmation_handler`): `Callable` sin threading.Event interno. El cliente decide si bloquea.
