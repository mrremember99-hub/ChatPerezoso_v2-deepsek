## Como se trabaja en este proyecto

### Testing

- `pytest -q tests/ 2>&1 | tail -3` - suite completa.
- `pytest -q tests/test_X.py 2>&1 | tail -5` - fichero concreto.
- `pytest --cov=core.X --cov-report=term-missing -q tests/test_X*.py`
  - cobertura de un modulo.

### Scripts de parche

Los `apply_*.py` de un solo uso van en `.gitignore`. Patron:

1. `cat > apply_X.py << 'PYEOF' ... PYEOF` con anchors unicos.
2. Cada patch: `assert src.count(old) == 1` + `raise SystemExit`.
3. `python3 apply_X.py` - si falla un anchor, no escribe nada.
4. `grep -n` post-aplicacion para verificar.
5. `pytest` antes de commitear.
6. Borrar el script al terminar (`rm -f apply_*.py`).

### Lecciones aprendidas (no repetir)

- **No anclar inserciones con `^    def \w+(`**. Puede caer
  entre un decorador (`@property`, `@Slot`) y su `def`, dejando
  el decorador huerfano.
- **Checks de "ya presente" por `def nombre(`**, nunca por
  nombre suelto (aparece en imports/comentarios y da falso skip).
- **`git diff` antes de `pytest`** tras cada parche.
- **`--amend` para arreglar un commit no pusheado**.
- **Heredocs**: si un bloque falla o se queda colgado en `>`,
  dividir en partes. Evitar bloques markdown ` ``` ` dentro de
  heredocs grandes.
- **Reemplazos regex**: usar `str.replace` con anchors unicos
  cuando sea posible, o `re.subn(pattern, lambda _m: repl, src)`
  para evitar que `\w`, `\b` se interpreten como escapes.
